## 4. Product Design Direction

MeetFlow AI is a meeting intelligence workspace, not a generic analytics dashboard.

Our visual inspiration:

- **Fathom:** Recording-first workflows, transcript, summary, highlights, and contextual actions.
- **Linear:** Compact navigation, typography, density, and precise alignment.
- **Raycast:** Keyboard interactions, search, and polished controls.
- **Apple:** Visual clarity, restrained motion, and excellent details.

Use these as references, not pixel-for-pixel templates.

### Brand personality

- Intelligent
- Professional
- Calm
- Focused
- Trustworthy
- Modern
- Refined

### Design principles

- Content takes priority over decoration.
- Clear visual hierarchy.
- Compact but readable navigation.
- Minimal unnecessary cards.
- Subtle borders and separators.
- Consistent typography.
- Strong spacing rhythm.
- Restrained accent color.
- Excellent light and dark themes.
- Responsive at normal browser zoom.
- Functional interactions rather than decorative controls.

Avoid the appearance of an automatically generated generic SaaS dashboard.

## 5. Visual Identity

Create a distinct MeetFlow AI design identity.

### Color direction

Use a sophisticated neutral foundation:

- Warm or cool off-white surfaces in light mode.
- Deep charcoal surfaces in dark mode.
- Subtle neutral borders.
- High-contrast primary text.
- Carefully differentiated secondary and muted text.
- One restrained primary accent.

Prefer a refined blue, teal, or similarly professional accent.

Avoid excessive orange, neon gradients, large colored backgrounds, and decorative glowing cards.

Use semantic tokens rather than hardcoded colors.

### Typography

Use Geist or Inter if already configured.

Define:

- Display
- H1
- H2
- H3
- H4
- Body large
- Body default
- Body small
- Caption
- Label
- Monospace

### Recommended UI density

At 100% browser zoom:

- Sidebar labels: approximately 12–13px.
- Standard body: approximately 13–15px.
- Navigation icons: 16–18px.
- Navigation rows: 32–36px.
- Compact buttons: approximately 32–36px.
- Main page titles: approximately 24–32px.
- Small section titles: approximately 14–18px.

Do not use oversized headings, giant buttons, or excessive padding.

Maintain accessible hit targets where practical.

## 9. App Shell and Navigation Architecture

Establish the reusable layout architecture for future dashboard pages.

The shell must be reliable, compact, and responsive.

### Desktop

- Sidebar approximately 208–224px expanded.
- Collapsed sidebar approximately 56–64px.
- Top header approximately 52–56px.
- Main content fills remaining width.
- Sidebar and content should not cause horizontal overflow.
- Stable layout during collapse.
- No awkward shifting or clipped icons.

### Sidebar scrolling

Implement correct layout boundaries.

- The application shell occupies the viewport height.
- Sidebar has a fixed header region.
- Navigation can scroll independently only when necessary.
- Account/footer controls remain pinned to the bottom.
- No accidental nested scrollbars.
- No sidebar content overflowing into the footer.
- Use appropriate flex sizing, `min-height: 0`, and overflow containment.

### Collapsed state

- Show icons centered consistently.
- Hide text labels without leaving awkward spacing.
- Show accessible tooltips for icon-only navigation.
- Preserve active navigation state.
- No text wrapping or clipped labels.
- No hover-triggered accidental expansion.
- Smooth but restrained width transition.
- Respect reduced-motion preferences.

### Mobile

- Sidebar becomes a dismissible drawer.
- Main content uses full available width.
- Navigation closes after selection.
- No horizontal page overflow.
- Keyboard and screen-reader accessible controls.

### Navigation model

Prepare the information architecture for:

- Meetings.
- Action Items.
- Calendar.
- Ask MeetFlow.
- Settings.

The primary experience should be meeting-first.

Do not put `/design` in normal customer navigation.

Do not add meaningless dashboard pages or decorative menu items.

### Scope

Implement the reusable shell and navigation behavior only.

Do not implement the actual meeting library, meeting detail workspace, or other product pages yet.

Use minimal placeholder content to verify layout behavior.
