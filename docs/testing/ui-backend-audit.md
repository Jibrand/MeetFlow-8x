# UI and backend audit — 2026-11-02

Existing layouts, authentication and visual design are preserved. Create and Edit use accessible participant chips: Enter/Tab/blur commits, empty Backspace removes the last participant, and labelled X buttons remove individuals. Names are trimmed and case-insensitively unique. Edit replaces participants atomically in Neon; delete uses an accessible modal with Cancel focus, pending protection, real errors, retry and success feedback.

Action Items, Meeting Detail and Overview share optimistic task state. Pending controls are disabled with a spinner, failures restore only the affected item, and concurrent successful changes survive another item's rollback. Open/completed/overdue statistics update with task state and reconcile with database counts. Real meeting/task data supplies charts, search, sidebar counts and Calendar; loading never substitutes seeded content.

Skeleton backgrounds are slightly darker in light mode, with matching card, calendar-grid, detail-column, task-row and overview shapes. Initial loads show skeletons, empty workspaces show explicit empty states, and errors remain visible with retry. Cached real data is retained on background failure.

## Follow-up: transaction lifecycle, participant extraction and server paging

Finalization previously performed an unbounded sequence of task writes inside Prisma's default five-second interactive transaction. The reported failure at the final job upsert is consistent with expiration after these earlier writes; OpenAI was already outside the transaction. Finalization now takes a guarded meeting-row lock, reads existing task titles once, deduplicates extracted tasks and performs batch inserts. Summary, participants, READY and COMPLETED/100% commit atomically. Existing tasks and manually maintained participants are retained. Database-only scopes use an explicit 15-second timeout with at most two fresh-scope retries on P2028/P2034. An expired persistence scope does not repeat analysis. Segment/media persistence is guarded, and completed job redelivery is harmless.

New-meeting forms no longer collect participants. The model extracts explicit identities and roles/emails; parser speaker labels provide grounded fallback names. Roles are nullable when not stated. Participants are merged case-insensitively without inventing diarization or overwriting manual edits.

The Meetings screen now requests nine records per server page, with debounced search, server filtering/sorting, deterministic ordering and a matching concurrent Neon index. Creation cancels stale in-flight reads, inserts the acknowledged meeting immediately, deduplicates the cache and resets to the first unfiltered page. Empty processing queues no longer poll or cause the application shell to download the archive. Calendar/Overview retain their existing full-data views. The current sidebar already contains no attribution/credit line; navigation and the pinned account menu remain intact.

Safe error messages replace internal URLs, ports, raw exceptions and processing diagnostics in visible screens/toasts. Development offline text is exactly “Backend not connected. Please try again.” Production shows friendly connection failure text and Retry. Server 5xx responses are safe in every environment; full diagnostics remain server-side. Network failure during refresh preserves the session hint so a temporary outage does not masquerade as invalid credentials.
